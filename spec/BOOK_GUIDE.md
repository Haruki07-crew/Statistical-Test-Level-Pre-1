# 教科書（章ごとの本文）の書き方

辞典（用語ごとのページ）は「引いて調べる」ためのもの。教科書は「頭から順に読み通して理解する」ためのもの。
同じ内容を辞典の言い換えで並べるのではなく、**1つの問いから出発して、概念を順に積み上げる物語**として書く。

## 置き場所と公開

- 本文：`content/<級>/book/chNN.md`（準1級は `content/book/`）。章番号はその級の章番号と同じ。
- 検算：`verify/<級>/book/chNN.py`（準1級は `verify/book/`）。`verify/bookcheck.py` の `Book` を使う。
- `JD_LEVEL=<級> .venv/bin/python scripts/check_book.py --ch N` で検算し、結果をハッシュつきで記録する。
  build.py は「検算に通り、そのあと本文が変わっていない章」だけ公開する（ほかは目次に「準備中」）。
- 統計学の教科書（tb）の学部の章（第1〜44章）は、2級・準1級の教科書の章を同じ順に並べて共通で使う。修士の章（第45章〜）だけ `content/tb/book/` に書く。

## 前付け

```yaml
---
chapter: 1
title: データの種類とグラフ        # 省略するとその級の章名
goals:                              # この章のねらい（3〜5 個、「〜できる」で終える）
  - データを質的変数と量的変数に分け、尺度水準を判定できる
prereq: 中学の数学（割合・平均）     # 前提
terms: [data-types, ...]            # この章の中心の用語（本文の [[ ]] のリンクも自動で足す）
charts: [...]                       # この章だけの図（用語ページと同じ書き方）
---
```

## 本文の組み立て

1. `## はじめに` … 具体的な問い・場面から入り、この章で何ができるようになるかを書く。
2. 番号つきの節（`## 1.1 〜`）… 動機 → 定義 → 性質・導き方 → 例題 の順。式は「なぜその形になるか」を言葉でも説明する。
3. `## まとめ` … 箇条書きで、章の要点を 5〜8 個。
4. `## 章末問題` … 3〜6 問。`:::問題` と `:::解答` の組。計算・解釈・正誤の判断を混ぜる。

## 囲み

```
:::定義 題名        （番号つき：定義・定理・命題・例題・問題。番号は「章.通し番号」）
本文（Markdown・数式が使える）
:::

:::解答            （直前の例題・問題の解答。たたんで表示）
方針 → 途中式 → 答え → 間違えやすい点 の順
:::
```

番号なし：`例`（短い具体例）・`ポイント`・`注意`（よくある誤解）・`発展`（読み飛ばしてよい）・`コラム`。囲みの入れ子はできない。

## リンクと図

- `[[用語id]]`・`[[用語id|表示する文字]]` … 辞典の用語ページへ。最初に出てきたところでリンクする（同じ用語に何度もリンクしない）。
- `{{chart 1}}` … 前付けの charts の 1 番目。`{{chart 用語id 1}}` … 用語ページの 1 番目の図を使う（同じ図を二重に持たない）。

## 品質のルール

- 文章・例・数値はすべてオリジナル。参考書・過去問・Web の文章を写さない。
- 本文の数値（例題の答え・表・図の値）は、すべて検算スクリプトで計算し直し、`b.num("何の値", 計算値, "本文に書いた数字")` で照合する。
- 2級は高校数学（Σ・平方根・指数）までで読めるようにし、微分積分は「発展」に回す。準1級は微分積分・線形代数を使い、導出を省かない。修士の章は測度論的な記法を使ってよいが、直観的な説明を必ず添える。
- 1 章の本文は、数式を除いて 3,000 字以上（2級で 5,000〜9,000 字、準1級・修士は数式が多いので 3,500〜8,000 字程度）を目安にする。字数より、導出を省かず例題で確かめることを優先する。
- 長いインライン数式は表示数式にする（スマホで横にはみ出さないように）。箇条書きの中に表示数式を入れない。
